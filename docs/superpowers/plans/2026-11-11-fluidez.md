# Fluidez Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O app para de mexer sozinho e de perder o lugar da pessoa: nada empurra a tela depois de pintada, trocar de aba é instantâneo e volta no mesmo ponto, post novo espera um toque, toda animação é interrompível, nasce do gatilho e respeita movimento reduzido.

**Architecture:** Tudo em cima de `js/motion.js` (springs → `linear()`, WAAPI) e da View Transitions API nativa. Lógica decidível vira função pura exportada (testada em `tools/*.test.mjs` com stubs, importando o módulo real); o resto é verificado no navegador com um observador único (`watchMotion()` em `tools/ui-audit.mjs`) e um runner CDP sem dependência (`tools/perf.mjs`) que aplica 375x812 e CPU 4×.

**Tech Stack:** JS vanilla (ES modules), CSS, Supabase JS, Capacitor Android, `node --test` (Node 24).

**Spec:** `docs/superpowers/specs/2026-11-11-fluidez-design.md` (ler junto; os números de linha `arquivo:N` abaixo são do spec e podem ter andado).

## Global Constraints

- Sem dependência nova. Só `js/motion.js` + View Transitions nativa.
- Spring sempre (`SPRINGS.*` / `var(--spring-*)` com `var(--spring-*-dur)`); nunca `ease-out`/cubic-bezier fixo, exceto o fallback que `spring()` já tem.
- Animar só `transform` e `opacity`; `height` só no acordeão.
- Nenhuma View Transition acima de ~300 ms. Nenhum `setTimeout` que espera animação antes de aceitar input.
- Tudo novo checa `reducedMotion()`: troca instantânea, sem transform.
- Os dois skins (padrão e `html[data-skin="yt2016"]`, `css/skin-yt2016.css`); toda checagem de navegador roda nos dois. `tools/skinContrast.test.mjs` verde.
- Botão voltar do Android: dropdown → overlay → passo do histórico → feed → minimiza (`js/backButton.js`, `tools/backButton.test.mjs`) não regride.
- View Transitions: detectar `document.startViewTransition`; sem ela, troca instantânea. Não mudar `minWebViewVersion`.
- Rolagem é da janela (`window.scrollTo`), não de container por aba.
- Fora de escopo: espaçamento/tipografia, cor/contraste, acessibilidade de teclado/leitor, sync de playlists, animações decorativas novas.
- Cada task termina com `node --test tools/*.test.mjs` verde. Módulo `.js` alterado que não é importado por nenhum teste: checar com cópia `.mjs` (`cp js/x.js "$TMP/x.mjs" && node -e "import('file:///'+process.argv[1])" "$TMP/x.mjs"`) — `node --check` não pega erro de módulo.
- Não commitar sem pedido do dono. Os passos "Commit" abaixo só rodam quando o dono autorizar; mensagem em português, terminando em `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Como medir (vale para todas as tasks com passo "Medir")

- Servidor de teste deslogado: copiar a árvore de trabalho (com as mudanças da task) para o scratch — `git ls-files -co --exclude-standard | tar -cT - | tar -x -C "$SCRATCH/site"` —, apagar o valor de `SUPABASE_URL` em `$SCRATCH/site/js/config.js` (vira "modo local"), `python -m http.server 5174 -d "$SCRATCH/site"`. Nunca mexer no `js/config.js` do repo.
- Chrome com depuração: `"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="$SCRATCH/chrome" --headless=new`.
- Rodar cenário: `node tools/perf.mjs --url http://localhost:5174/ --scenario tools/perf/<nome>.js --skin default` e de novo com `--skin yt2016`. Saída: uma linha JSON por skin, com `pass: true|false`.

## Review Focus

1. Pessoa toca de novo durante qualquer animação nova (acordeão a 50%, swipe antes de assentar, menu fechando, View Transition no meio): continua do ponto atual, nada salta, toque atendido no quadro seguinte. → testes nas Tasks 3, 6, 9, 12.
2. Prévia de link que falha, demora ou não tem imagem; mesmo URL em vários posts e no chat ao mesmo tempo: nenhum salto e nenhum skeleton órfão. → Task 1.
3. Volta pelo botão do Android com aba mantida / perfil de outro usuário / popover fechando: ordem do `backStep` intacta e rolagem restaurada. → Tasks 6, 7.
4. Buffer de posts novos vazando por um caminho de render que não seja `refreshFromServer()` (publicar, filtro, `refreshPostsView`, `renderFeedTab`) e reposts em "Seguindo". → Task 11.
5. Falha de rede numa ação rápida repetida (curtir→descurtir→curtir com erro no meio): estado final igual ao servidor, inverso roda uma vez, um toast. → Task 5.
