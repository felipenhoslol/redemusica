# Easter egg "2016" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 16 cliques no gato do logo trocam o app inteiro para um visual fiel ao YouTube de 2016 (claro e escuro) e um gato retrô; depois disso as configurações ganham a seção "Visual" para ir e voltar, tudo por conta.

**Architecture:** A lógica pura (qual visual vale para qual id, contador de cliques, reconciliação da descoberta) fica em `js/look.js`, sem imports, testável no Node. O script inline do `<head>` repete a resolução em ES5 para aplicar `data-skin`/`data-cat` antes da pintura; um teste roda esse script de verdade contra a mesma tabela. `js/easterEgg.js` liga os cliques e as animações; `css/skin-yt2016.css` (carregado por último, tudo sob `[data-skin="yt2016"]`) faz a pele. A descoberta vai para o servidor como `extras.easterEgg2016`, mesclada com OR.

**Tech Stack:** Vanilla JS ES modules sem build, Supabase (`profiles.extras`), Capacitor Android, WAAPI via `js/motion.js`, testes `node --test tools/*.test.mjs` (padrão do repo: `tools/sync.test.mjs`, `tools/backButton.test.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-03-easter-egg-yt2016-design.md`

## Global Constraints

- Gatilho: 16 cliques no gato do sidebar (`.sidebar-logo`, `js/app.js:183`) ou do header mobile (`.mobile-brand`, `js/app.js:280`); contador zera após 2000 ms sem clique; cada clique continua navegando para o feed.
- Nenhuma pista: sem contador, tooltip, vibração, animação que cresce, `console.log`, nem texto nas configurações para quem não descobriu.
- Nunca escrever "YouTube" em UI, textos, `alt`, `aria-label`, título da aba, nomes de classe visíveis ou comentários de CSS que vão para produção. A opção se chama "2016", descrição "Visual retrô de 2016".
- Valores do armazenamento: `skin: 'padrao' | 'yt2016'`, `cat: 'kawaii' | 'retro'`; o egg grava `skin='yt2016'` **e** `cat='retro'`, sempre.
- Visual acompanha a identidade (conta logada ou modo local). Sem identidade conhecida (tela de login) = padrão. Descoberto = espelho local daquele id OU `extras.easterEgg2016 === true`; nada "desdescobre".
- Skin padrão idêntica a hoje: nenhum arquivo CSS existente é editado para a pele (`feed.css`, `chat.css`, `profile.css`, `mobile.css`, `ranking.css`, `auth.css` etc.); só `index.html` ganha o `<link>` e o script do head.
- Motion: só `animateSpring`/`SPRINGS`/`reducedMotion` de `js/motion.js`; só `transform`/`filter`/`opacity`; nada em volta do gato se mexe.
- Paleta clara e escura: valores das tabelas da spec; contraste AA (4.5:1 texto, 3:1 texto grande/ícone) medido, ajustando valores e não o critério.
- Share cards (`js/storyImage.js`) sempre com o gato padrão.
- Commits em português no estilo do repo, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `node --check` não pega erro de módulo `.js`: toda verificação de sintaxe é pelo `import` real nos testes.

3. **Duas contas no mesmo aparelho**: a que não descobriu vê padrão e não vê a seção. Pinado na tabela de `resolveLook` (Task 1) e no teste do head script (Task 2).

5. **Cliques durante a sequência do 16º / re-render do sidebar no meio da contagem**: esperado uma única recarga e contagem preservada. O contador vive no módulo e o listener é delegado no `document` (Task 5, steps de verificação).
